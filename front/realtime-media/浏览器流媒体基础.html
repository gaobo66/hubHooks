MSE（Media Source Extensions） ​

功能就是让 JS 可以把音视频数据“推”给 video 标签

我们可以看一下大致的代码

typescript
const video = document.getElementById('video');

// 1.创建 MediaSource（一个“空壳播放器”）
const mediaSource = new MediaSource();
// <video> 没有真实的 mp4 地址，而是给了它一个 “虚拟媒体源”
video.src = URL.createObjectURL(mediaSource);

// 2.MediaSource 准备好后，才能往里加 SourceBuffer
mediaSource.addEventListener('sourceopen', async () => {

    // 告诉浏览器：接下来我会给你 H.264 的 mp4 数据
    const mime = 'video/mp4; codecs="avc1.42E01E"';
    const sourceBuffer = mediaSource.addSourceBuffer(mime);

    // 3.请求服务器的 fMP4 流
    const resp = await fetch('/stream');
    const reader = resp.body.getReader();

    // 4.不断读取服务器推过来的二进制数据
    while (true) {
        const {done, value} = await reader.read();
        if (done) {
            mediaSource.endOfStream();
            break;
        }

        // 5.把这一小段视频数据交给浏览器
        sourceBuffer.appendBuffer(value);
    }
});

FFmpeg ​

FFmpeg 是一个开源、免费、功能极其强大的跨平台音视频处理解决方案。它既是一个命令行工具集，也是一套* 音视频编解码和流处理的开发库*。

你可以把它理解为 “音视频处理的瑞士军刀” 或 “音视频领域的命令行超级工厂”。

它几乎能做所有与音视频相关的事情：

  • 编解码（decode/encode）
  • 格式转换（transmux）
  • 推流 / 拉流
  • 视频截图 / 拼接 / 裁剪 / 水印
  • 流媒体服务器中间层
  • 甚至可以实时采集摄像头、麦克风数据

官方介绍：What is FFmpeg

架构组成 ​

FFmpeg 项目主要由三个核心的命令行工具组成：

  1. ffmpeg：最核心的工具。
    • 功能：用于格式转换、编码、解码、抓取、流化、滤镜处理等几乎所有音视频操作。
    • 命令模式：ffmpeg -i [输入文件] [参数选项] [输出文件]
    • 示例：将 MP4 转成 AVI：ffmpeg -i input.mp4 output.avi
  2. ffplay：
    • 功能：一个简单的、基于 FFmpeg 库的媒体播放器。常用于快速测试和调试媒体文件。
    • 示例：播放一个文件：ffplay myvideo.mp4
  3. ffprobe：
    • 功能：一个多媒体流分析工具。用来查看媒体文件的详细信息（元数据、编码格式、码率、分辨率、时长、流结构等）。
    • 示例：查看文件信息：ffprobe -v quiet -show_format -show_streams input.mp4

在命令行工具的背后，是一系列功能强大的开发库，如 libavcodec（编解码库）、libavformat（封装/解封装库）、libavfilter （滤镜库）等，这些库可以被其他程序调用。

组件作用
ffmpeg命令行工具，用于转码、推流、录制等（最常用）
ffplay一个轻量播放器，用来测试视频流是否可播放
ffprobe分析媒体文件信息（分辨率、码率、帧率、时长等）
libavcodec音视频编解码核心库
libavformat封装与解封装容器格式，如 mp4、flv、mkv、ts
libavfilter视频滤镜处理，如水印、特效、裁剪等
libavdevice采集设备输入，如摄像头、麦克风
libswscale像素格式/分辨率转换
libswresample音频采样率转换

常见的命令 ​

  1. 视频转封装

    ffmpeg -i input.avi output.mp4
    1

    把 .avi 转成 .mp4 格式。

  2. 截取视频片段

    ffmpeg -ss 00:00:05 -t 10 -i input.mp4 output.mp4
    1

    从第5秒开始，截取10秒。

  3. 推流到本地服务器（常用于直播）

    ffmpeg -re -i video.mp4 -c copy -f flv rtmp://localhost/live/stream
    1

    说明：

    • -re 表示按正常播放速度读取（模拟实时）
    • -f flv 表示输出格式是 FLV（RTMP 需要）
    • rtmp://... 是目标流媒体服务器地址

  4. 把摄像头采集的画面推流

    ffmpeg -f dshow -i video="Integrated Camera" -f flv rtmp://localhost/live/stream
    1

    Windows 下从摄像头读取画面并实时推送。

  5. 拼接多个视频（模拟多路监控）

    ffmpeg \
  -i cam1.mp4 -i cam2.mp4 -i cam3.mp4 -i cam4.mp4 \
  -filter_complex "xstack=inputs=4:layout=0_0|w0_0|0_h0|w0_h0" \
  output.mp4
    1
    2
    3
    4

    这会生成一个四分屏视频。

HLS/DASH ​

要让流媒体具备生产–分发–播放全链路能力，简单来说，就是：

  • 切片规则
  • 清晰度自适应（ABR）
  • CDN 缓存策略
  • 加密与版权控制
  • 播放列表（时序 & 更新机制）

这些都需要考虑，所以后面就有了HLS和DASH，这两个相当于制定了一些流媒体标准，

  • HLS：苹果公司主导的流媒体协议，最初为iOS设计，现已成行业标准
  • DASH：国际标准组织（MPEG）制定的开放标准，更灵活强大

WebRTC ​

WebRTC（Web Real-Time Communication） 是一套由浏览器原生支持的实时音视频通信技术标准，它允许浏览器之间直接传输：

  • 音频（Audio）
  • 视频（Video）
  • 任意数据（DataChannel）

最重要的是：不需要安装任何插件！

WebRTC不是流媒体协议，而是实时通信框架，主要解决超低延迟的双向音视频通信

WebRTC和HLS/DASH对比 ​

WebRTC不是流媒体协议，而是实时通信框架，主要解决超低延迟的双向音视频通信

HLS我们需要服务器转发流媒体数据，而WebRTC可以点对点的直接传递流媒体数据

特性HLS/DASHWebRTC
通信方向单向（服务器 → 客户端）双向 / 多向（点对点 / 服务器中继）
核心场景一对多广播（直播、点播）实时互动（视频通话、连麦、低延迟互动直播）
数据传输方式服务器转发流媒体切片（如 fMP4/TS）点对点直传（P2P）或服务器中继（SFU/MCU）
延迟水平秒级延迟（HLS 通常 3~10s）毫秒级延迟（一般 50~500ms）
