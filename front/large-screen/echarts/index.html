ECharts 完整渲染链路 ​

大概分为3个阶段

  1. 配置阶段: 合并 option、补默认值，建立组件和系列模型 ECharts 上层业务层
  2. 计算阶段: 数据处理、视觉映射、布局计算，确定图形位置与样式 ECharts 中间计算层
  3. 渲染阶段: 图形对象交给 ZRender，输出到 Canvas 或 SVG ZRender 底层渲染层

TIP

性能瓶颈通常在后半段：布局计算、图形更新、重绘

交互频繁时，setOption() 只是入口，真正的开销在后续计算与渲染环节

ZRender 是性能优化的核心阵地：脏矩形、渲染模式切换、事件优化都依赖它

ZRender ​

ECharts 不直接操作Canvas或 SVG，而是把图形元素、交互事件和重绘过程交给ZRender 承接。

echarts 默认使用canvas渲染。

javascript
const chart = echarts.init(dom, null, {renderer: 'svg'})
1

canvas vs svg ​

canvas ​

优势：

  • 大数据量场景
  • 频繁更新或动画较多、实时刷新
  • 更关注吞吐量而不是 DOM结构

劣势：

  • 放大后 图片会失真，不如svg（矢量图）清晰
  • 文本和节点不不具备独立dom，不能直接操作，需要通过zrender api操作

svg ​

优势：

  • 低等到中等数据量场景
  • 需要高清缩放
  • 移动端和静态展示场景

劣势：

  • 节点太多时dom成本高
  • 高频重绘不如canvas稳定

Canvas 本身不支持独立图形事件，但 ZRender 已通过虚拟图形树 + 坐标碰撞检测模拟了完整事件系统，用法与 SVG 完全一致，

建议

数据量大或更新频繁优先canvas 强调缩放清晰度和轻量展示可考虑svg

脏矩形优化（useDirtyRect） ​

脏矩形优化的本质是减少 Canvas 绘制操作：

一句话理解：不是 “少算数据”，而是 “少重绘画面”

核心思路 ​

ECharts 图表更新时，不必把整张画布全部重绘，而是通过脏矩形（Dirty Rect）技术：

  1. 只标记「发生变化的区域」（脏区域）
  2. 仅将这部分区域交给底层渲染器重新绘制
  3. 大幅降低重绘开销，提升高频更新场景的性能
javascript
// 初始化图表（Canvas 渲染 + 开启脏矩形）
const chart = echarts.init(dom, null, {
    renderer: 'canvas', // 必须指定 Canvas
    useDirtyRect: true, // 开启 ZRender 脏矩形优化
});

chart.setOption(option); // 后续更新自动触发局部重绘

使用判断与收益场景 ​

推荐开启场景

  1. 实时数据刷新（如大屏监控、实时折线 / 柱状图）
  2. 拖拽 / 缩放交互（如地图缩放、图表平移）
  3. 局部高亮动画（如 tooltip 悬浮、元素高亮）

不推荐开启场景

  1. 静态图、低频更新页面：收益不明显，无需额外配置
  2. SVG 渲染模式：不支持该能力，开启无效

流式数据（如实时监控、日志曲线）追加，优先用 appendData，禁止高频 setOption

原因：每次调用 setOption 都会触发完整的配置 diff、全量重计算、全量重绘，数据量越大、频率越高，卡顿越明显。

而 appendData 只处理新增数据部分，跳过全量 diff，仅做增量渲染，性能比 setOption 提升 10~100 倍。

appendData 限制

  • 仅支持数据追加，不支持数据修改、删除，若需全量更新仍需用 setOption
  • 仅适用于折线图、柱状图等支持数据追加的系列，饼图、散点图等不适用

ECharts 工程化 ​

工程约束 ​

  1. 生命周期管理
    • 初始化、更新、销毁放进 Hook 或基础组件，业务层不要到处手写 init / dispose
  2. 配置结构稳定
    • 坐标系、图例、tooltip、series 的结构尽量固定，数据变化只改必要字段
  3. 更新策略提前定好
    • 哪些场景走全量 setOption，哪些场景走局部更新，最好在封装层就统一掉
  4. 样式口径不分散
    • 颜色、字号、边距尽量从公共配置或常量里出，避免每个 option 单独拼接

常见问题 ​

  1. 容器高度为 0，ECharts 初始化时容器必须有明确高度，使用 CSS 显式设置 height

  2. 内存泄漏！必须在 onUnmounted 中调用 chart.dispose()

  3. 多次 init 同一 DOM 会报错！使用 echarts.getInstanceByDom(dom) 先检查再 init

  4. resize 监听未清理 组件卸载时，必须在 onUnmounted 中移除 resize 事件监听，否则内存泄漏

useECharts Hook ​

  1. useECharts Hook
ts

import * as echarts from 'echarts'
import type {EChartsOption, SetOptionOpts} from 'echarts'
import {ref, onMounted, onUnmounted, type Ref} from 'vue'

export function useECharts(
    containerRef: Ref<HTMLElement | undefined>,
    initialOption: EChartsOption
) {
    // 图表实例引用
    const chart = ref<echarts.ECharts | null>(null)
    // 尺寸监听器实例
    let ro: ResizeObserver | null = null

    // 组件挂载时初始化图表
    onMounted(() => {
        // 容器不存在则直接返回，避免报错
        if (!containerRef.value) return

        // 1. 初始化 ECharts 实例
        chart.value = echarts.init(containerRef.value)
        // 2. 渲染初始配置
        chart.value.setOption(initialOption)

        // 3. 监听容器尺寸变化，自动 resize 图表
        // 比全局 window.resize 更精准、性能更好
        ro = new ResizeObserver(() => chart.value?.resize())
        ro.observe(containerRef.value)
    })

    // 组件卸载时销毁资源
    onUnmounted(() => {
        // 断开尺寸监听
        ro?.disconnect()
        // 销毁图表实例，释放内存
        chart.value?.dispose()
        // 清空实例引用
        chart.value = null
    })

    // 暴露更新图表配置的方法
    const setOption = (
        option: EChartsOption,//图表配置(数据、折线、柱状、颜色)
        opts?: SetOptionOpts//更新配置(覆盖 / 合并、是否立即刷新)
    ) => chart.value?.setOption(option, opts)

    // 返回实例引用和更新方法
    return {chart, setOption}
}

            type: s.type,
            data: s.data

          {name: '线下', type: 'line', data: newData.map(d => d.offline)}

内存管理：ChartManager 统一生命周期治理 ​

彻底解决 SPA 项目中，路由切换、组件销毁导致的 ECharts 实例内存泄漏问题，统一管理所有图表实例的生命周期。

ts
class ChartManager {
    // 用 Map 统一存储所有图表实例
    private instances = new Map<string, echarts.ECharts>()

    /**
     * 初始化图表实例
     * @param id 实例唯一标识
     * @param dom 挂载容器
     */
    init(id: string, dom: HTMLElement): echarts.ECharts {
        // 防止重复初始化同一 DOM
        if (this.instances.has(id)) return this.instances.get(id)!

        const chart = echarts.init(dom)
        this.instances.set(id, chart)
        return chart
    }

    /**
     * 销毁指定图表实例
     * @param id 实例唯一标识
     */
    dispose(id: string): void {
        const chart = this.instances.get(id)
        if (!chart) return

        // 销毁实例，释放内存
        chart.dispose()
        this.instances.delete(id)
    }

    /**
     * 销毁所有图表实例
     * 用于 SPA 路由切换、页面卸载时
     */
    disposeAll(): void {
        this.instances.forEach(c => c.dispose())
        this.instances.clear()
    }

    /**
     * 获取指定图表实例
     * @param id 实例唯一标识
     */
    getInstance(id: string): echarts.ECharts | undefined {
        return this.instances.get(id)
    }
}

// 导出单例，全局统一管理
export const chartManager = new ChartManager()

// ==============================================
// 1. 独立功能：ChartManager（全局实例管理）
//  src/hooks/echarts/ChartManager.ts
// ==============================================
import * as echarts from 'echarts'

import * as echarts from 'echarts'

class ChartManager {
    private instances = new WeakMap<HTMLElement, echarts.ECharts>()

    // 初始化：传入 DOM，自动存储
    init(dom: HTMLElement): echarts.ECharts {
        const exist = this.instances.get(dom)
        if (exist) return exist

        const chart = echarts.init(dom)
        this.instances.set(dom, chart)
        return chart
    }

    // 销毁：通过 DOM 销毁
    dispose(dom: HTMLElement): void {
        const chart = this.instances.get(dom)
        if (!chart) return

        chart.dispose()
        this.instances.delete(dom)
    }

    // 批量销毁
    disposeAll(): void {
        this.instances.forEach(chart => chart.dispose())
        this.instances = new WeakMap()
    }
}

export const chartManager = new ChartManager()

import * as echarts from 'echarts'
import type { EChartsOption, SetOptionOpts } from 'echarts'

export function useChartPerf(chart: echarts.ECharts) {
    // 监听渲染完成
    const listenRendered = () => {
        chart.getZr().on('rendered', () => {
            performance.mark('echarts-rendered')
        })
    }

    // 带性能统计的 setOption
    const setOptionWithPerf = (
        option: EChartsOption,
        opts?: SetOptionOpts
    ) => {
        const start = performance.now()
        chart.setOption(option, opts)
        console.log('✅ setOption 耗时:', performance.now() - start + 'ms')

        const model = chart.getModel()
        console.log('📊 系列数量:', model.getSeries().length)
        console.log('📊 数据量:', model.getSeries()[0]?.getData().count() || 0)
    }

    return {
        listenRendered,
        setOptionWithPerf
    }
}

// 4. 独立功能：useECharts（开放性能开关）
//  src/hooks/echarts/useECharts.ts
// ==============================================
import * as echarts from 'echarts'
import type { EChartsOption, SetOptionOpts } from 'echarts'
import { ref, onMounted, onUnmounted, type Ref } from 'vue'
import { chartManager } from './ChartManager'
import { useChartPerf } from './useChartPerf'


export function useECharts(
    containerRef: Ref<HTMLElement | undefined>,
    initialOption: EChartsOption,
    enablePerformance = false
) {
    const chart = ref<echarts.ECharts | null>(null)
    let ro: ResizeObserver | null = null
    let perfHook: ReturnType<typeof useChartPerf> | null = null

    onMounted(() => {
        const dom = containerRef.value
        if (!dom) return

        // ================================
        // ✅ 【正确关联 ChartManager】
        // 创建图表实例并关联到 DOM 元素上
        // ================================
        chart.value = chartManager.init(dom)

        chart.value.setOption(initialOption)

        // 性能监控
        if (enablePerformance && chart.value) {
            perfHook = useChartPerf(chart.value)
            perfHook.listenRendered()
        }

        // 自适应
        ro = new ResizeObserver(() => chart.value?.resize())
        ro.observe(dom)
    })

    onUnmounted(() => {
        ro?.disconnect()
        const dom = containerRef.value
        if (dom) {
            // ================================
            // ✅ 【正确销毁】
            // 销毁图表实例并从 ChartManager 中移除关联
            // ================================
            chartManager.dispose(dom)
        }
        chart.value = null
    })

    const setOption = (option: EChartsOption, opts?: SetOptionOpts) => {
        if (!chart.value) return
        if (enablePerformance && perfHook) {
            perfHook.setOptionWithPerf(option, opts)
        } else {
            chart.value.setOption(option, opts)
        }
    }

    return { chart, setOption }
}

  import { ref, onMounted } from 'vue'
  import { useECharts } from '@/hooks/echarts/useECharts'
  import { buildOption } from '@/hooks/echarts/buildOption'

  // ======================
  // 1. 模板引用
  // ======================
  const chartContainer = ref<HTMLElement | undefined>()

  // ======================
  // 2. 图表配置
  // ======================
  const baseConfig = ref({
    title: '月度销售数据',
    xData: ['1月', '2月', '3月', '4月', '5月'],
    series: [
      {
        name: '销售额',
        type: 'bar' as const,
        data: [120, 200, 150, 240, 220]
      }
    ]
  })

  // 保存初始配置
  const initialConfig = structuredClone(baseConfig.value)

  // ======================
  // 3. ✅ 正确初始化（只有3个合法参数）
  // ======================
  // 参数1：容器DOM ref
  // 参数2：初始option（这里先传空，后面统一渲染）
  // 参数3：开启性能监控
  const { chart, setOption } = useECharts(
      chartContainer,
      buildOption(baseConfig.value),
      true
  )

  // ======================
  // 4. 统一渲染函数
  // ======================
  function renderChart() {
    const option = buildOption(baseConfig.value)
    setOption(option)
  }

  // ======================
  // 5. 更新数据
  // ======================
  function updateData() {
    baseConfig.value.series[0].data = baseConfig.value.xData.map(
        () => Math.floor(Math.random() * 300)
    )
    renderChart()
  }

  // ======================
  // 6. 切换图表类型
  // ======================
  function switchChartType() {
    const currentType = baseConfig.value.series[0].type
    baseConfig.value.series[0].type = currentType === 'bar' ? 'line' : 'bar'
    renderChart()
  }

  // ======================
  // 7. 重置图表
  // ======================
  function resetChart() {
    baseConfig.value = structuredClone(initialConfig)
    renderChart()
  }
</script>

大屏可视化优化经验 ​

常规方案 ​

  1. 数据刷新策略：大屏不是小页面，数据更新要保证不闪烁、不崩溃、稳定、实时

    • 轮询间隔 ≥ 30s
    • WebSocket 实时推送
    • 增量更新避免闪烁+配合 脏矩形优化（useDirtyRect）

  2. 字体渲染问题

    • 大屏字体必须清晰，SVG 渲染模式更清晰
    • Canvas 模式下设置 pixelRatio: 2

  3. 性能红线

    指标安全阈值优化方案
    同屏图表数≤ 12 个超过阈值建议做分页、轮播、按需渲染，避免 CPU 过载
    单图数据量≤ 5000 条大数据量场景做数据采样、聚合、降频，避免一次性全量渲染
    动画时长≤ 600ms高频更新场景可关闭动画，避免阻塞渲染线程
    包体大小按需引入使用 ECharts 按需引入，仅注册用到的图表 / 组件，减小打包体积

性能优化三板斧 ​

  1. 数据采样

    js
    series: [{
  type: 'line',
  // lttb 算法：最大三角形三桶算法，自动降采样
  sampling: 'lttb',
  data: largeArray // 支持 100 万级数据
}]
    1
    2
    3
    4
    5
    6

    特点

    LTTB（Largest Triangle Three Buckets）算法：在不破坏整体趋势的前提下，自动对数据进行降采样 视觉失真极低，完美保留图表的整体走势、峰谷特征，仅减少绘制点数

    适用场景

    • 折线图、面积图等「趋势比单点更重要」的场景
    • 监控看板、时序数据、日志曲线等大数据量折线场景

  2. large 模式

    js
    series: [{
  type: 'scatter',
  large: true, // 开启大数据量散点优化
  largeThreshold: 2000, // 超过 2000 点自动启用
  data: millionPoints // 支持百万级散点
}]
    1
    2
    3
    4
    5
    6

    特点

    • 跳过逐点渲染，启用高性能批量渲染，直接用 Canvas 绘制所有点
    • 万级散点专用，支持 100 万级数据可视化
    • 牺牲部分样式和交互能力，换取极致渲染性能

    适用场景

    • 散点图、气泡图等「点非常多」的场景
    • 万级、百万级散点数据可视化

    注意事项

    • 部分样式（如渐变、复杂标签）和交互能力会受限
    • 需优先确认业务是否真的需要逐点效果，再决定是否开启

  3. dataZoom 按需加载

    js
    dataZoom: [{
  type: 'inside',
  start: 0,
  end: 10 // 初始只渲染 10% 数据
}]
    1
    2
    3
    4
    5

    优势

    • 初始仅渲染部分数据（如 10%），用户拖拽缩放时，再渲染对应区间的完整数据
    • 核心思路：不是把所有数据都画出来，而是先让用户看到最有价值的一段

    适用场景

    • 时序数据、日志曲线、监控看板等长周期大数据场景
    • 数据量极大、用户仅需关注局部区间的场景

    核心价值

    • 初始渲染速度提升 10 倍以上，避免页面卡顿
    • 完美适配大屏、监控等长时序数据展示需求

选择策略

折线图优先看 sampling:'1ttb'，散点图优先看 large:true，时序数据优先看 datazoom。如果三者都不够，再回头检查是不是数据结构、更 新频率或同屏图表数量本身已经超标。
