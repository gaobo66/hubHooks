Fetch ai ​

使用 `fetch` 函数即可立即向服务器发送网络请求

参数 ​

该函数有两个参数：

  1. 必填，字符串，请求地址
  2. 选填，对象，请求配置

请求配置对象

  • method：字符串，请求方法，默认值 GET
  • headers：对象，请求头信息
  • body: 请求体的内容，必须匹配请求头中的 Content-Type
  • mode：字符串，请求模式
    • cors：默认值，配置为该值，会在请求头中加入 origin 和 referer
    • no-cors：配置为该值，不会在请求头中加入 origin 和 referer，跨域的时候可能会出现问题
    • same-origin：指示请求必须在同一个域中发生，如果请求其他域，则会报错
  • credentials: 如何携带凭据（cookie）
    • omit：默认值，不携带 cookie
    • same-origin：请求同源地址时携带 cookie
    • include：请求任何地址都携带 cookie
  • cache：配置缓存模式
    • default: 表示 fetch 请求之前将检查下 http 的缓存.
    • no-store: 表示 fetch 请求将完全忽略 http 缓存的存在. 这意味着请求之前将不再检查下 http 的缓存, 拿到响应后, 它也不会更新 http 缓存.
    • no-cache: 如果存在缓存, 那么 fetch 将发送一个条件查询 request 和一个正常的 request, 拿到响应后, 它会更新 http 缓存.
    • reload: 表示 fetch 请求之前将忽略 http 缓存的存在, 但是请求拿到响应后, 它将主动更新 http 缓存.
    • force-cache: 表示 fetch 请求不顾一切的依赖缓存, 即使缓存过期了, 它依然从缓存中读取. 除非没有任何缓存, 那么它将发送一个正常的 request.
    • only-if-cached: 表示 fetch 请求不顾一切的依赖缓存, 即使缓存过期了, 它依然从缓存中读取. 如果没有缓存, 它将抛出网络错误(该设置只在 mode 为”same-origin”时有效).

返回值 ​

fetch 函数返回一个 Promise 对象

  • 当收到服务器的返回结果后，Promise 进入 resolved 状态，状态数据为 Response 对象
  • 当网络发生错误（或其他导致无法完成交互的错误）时，Promise 进入 rejected 状态，状态数据为错误信息

Response 对象

  • ok：boolean，当响应消息码在 200~299 之间时为 true，其他为 false
  • status：number，响应的状态码
  • text()：用于处理文本格式的 Ajax 响应。它从响应中获取文本流，将其读完，然后返回一个被解决为 string 对象的 Promise。
  • blob()：用于处理二进制文件格式（比如图片或者电子表格）的 Ajax 响应。它读取文件的原始数据，一旦读取完整个文件，就返回一个被解决为 blob 对象的 Promise。
  • json()：用于处理 JSON 格式的 Ajax 的响应。它将 JSON 数据流转换为一个被解决为 JavaScript 对象的 promise。
  • redirect()：可以用于重定向到另一个 URL。它会创建一个新的 Promise，以解决来自重定向的 URL 的响应。

强缓存和协商缓存 ​

强缓存（Strong Cache） ​

强缓存是在缓存未过期时直接使用本地缓存资源，不需要向服务器发送请求。其核心依赖 HTTP 头部中的 Cache-Control 和 Expires 字段。

工作流程：

  1. 资源请求

    浏览器首次请求资源时，服务器响应时会携带 Cache-Control: max-age=xxx 或 Expires 字段，指示资源可以在本地缓存多长时间。

TIP

Expires：资源到【某个具体时间】前有效:是HTTP/1.0 标准

javascript
Expires: Wed, 20 Mar 2026 10:00:00 GMT
1

max-age：资源从现在开始【多少秒内】有效:是HTTP/1.1 标准

javascript
Cache-Control: max-age=86400
1
  1. 缓存判读
  2. 直接使用缓存

协商缓存（Negotiation Cache） ​

协商缓存主要用于处理缓存过期或未命中强缓存时的情况。浏览器会向服务器发送带有条件的请求（如 If-Modified-Since 或 If-None-Match），让服务器判断资源是否发生变化

工作流程

  1. 请求资源 & 检查缓存

浏览器检查本地缓存资源。如果资源存在但已过期或未命中强缓存机制，则发起协商缓存流程。

  1. 发送条件请求

    浏览器在请求头中加入条件字段：

    • 方案1：If-Modified-Since：携带上次响应的 Last-Modified 时间。

      • 核心逻辑
        • Last-Modified（服务器响应头）：告诉浏览器「这个资源最后修改的时间」（比如 Last-Modified: Wed, 20 Mar 2026 08:00:00 GMT）；
        • If-Modified-Since（浏览器请求头）：下次请求时，把上次拿到的 Last-Modified 值带回去，问服务器「资源在这个时间之后有没有改过？」。
      • 缺点：
        1. 精度低：只能精确到秒，若资源 1 秒内多次修改，无法识别；
        2. 误判：文件内容没改，但修改时间变了（比如重新保存），会被判定为「已更新」，导致没必要的重新下载。

    • 方案2：If-None-Match：携带上次响应的 ETag 值。

      • 核心逻辑：
        • ETag（服务器响应头）：服务器给资源生成的「唯一指纹」（比如 ETag: "abc123def456"），资源内容变了，指纹就变；
        • If-None-Match（浏览器请求头）：下次请求时，把上次的 ETag 值带回去，问服务器「这个指纹对应的资源是不是最新的？」。
      • 服务器判断规则
        • 如果服务器当前资源的 ETag = If-None-Match → 没变化 → 返回 304；
        • 如果不相等 → 已更新 → 返回 200 + 新资源 + 新 ETag。
      • 优势
        • 精度高：基于内容哈希，哪怕 1 个字符变化，指纹就变；
        • 避免时间误判：不受文件修改时间影响，只看内容。

  2. 服务器判断

    服务器根据请求中携带的条件判断资源是否被修改：

    • 未修改：返回 HTTP 304 Not Modified 状态码，浏览器继续使用本地缓存数据。
    • 已修改：返回 HTTP 200 OK 状态码和最新资源，同时更新本地缓存。

总结 ​

  1. 强缓存：浏览器在缓存有效期内直接使用本地缓存，不产生网络请求，提高了响应速度，但无法感知资源的实时更新。​
  2. 协商缓存：当缓存失效时，通过条件请求与服务器协商，判断资源是否更新，保证数据的实时性，同时也能降低带宽消耗（304 响应体积小）。​ 通过这两种机制，HTTP 缓存既能提高访问速度，又能保证内容的最新性。
nginx
server {
    listen 80;
    server_name your-domain.com; # 替换成你的域名
    root /usr/share/nginx/html; # 静态资源根目录

    # 静态资源缓存配置（核心）
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        # 1. 强缓存配置（优先级最高）
        # max-age=31536000 表示缓存1年（单位：秒）
        # public：允许中间代理服务器缓存（CDN/网关）；若仅浏览器缓存用 private
        # immutable：告诉浏览器缓存期内不要发任何验证请求（进一步减少请求）
        add_header Cache-Control "public, max-age=31536000, immutable";
        
        # 兼容HTTP/1.0的Expires（max-age优先级更高，仅兜底）
        add_header Expires $expires_1y;

        # 2. 协商缓存配置（强缓存过期后生效）
        etag on; # 开启ETag（默认开启，显式声明更清晰）
        last_modified on; # 开启Last-Modified（默认开启）
        
        # 可选：优化ETag生成规则（避免分布式部署时ETag不一致）
        etag_hash on; # 基于文件内容哈希生成ETag（而非inode+size）
        
        # 3. 性能优化（非缓存，但建议加）
        gzip on; # 开启压缩
        gzip_types text/javascript text/css image/svg+xml;
        expires 1y; # 和Expires字段联动，Nginx内置变量
        
        # 4. 可选：禁止日志（减少磁盘IO）
        access_log off;
    }

    # HTML文件特殊配置：禁用强缓存，仅用协商缓存（保证页面能及时更新）
    location ~* \.html$ {
        add_header Cache-Control "public, max-age=0, must-revalidate"; # 强缓存立即过期
        etag on;
        last_modified on;
    }

    # 定义Nginx内置过期时间变量（可选，简化配置）
    map $sent_http_content_type $expires_1y {
        default off;
        text/javascript 1y;
        text/css 1y;
        image/png 1y;
        image/jpg 1y;
        image/jpeg 1y;
        image/gif 1y;
        image/ico 1y;
        image/svg+xml 1y;
        font/woff 1y;
        font/woff2 1y;
        font/ttf 1y;
        font/eot 1y;
    }
}
