异常体系 ​

Throwable — 所有错误和异常的父类
  ├── Error：严重错误，JVM层面，不应尝试处理
  │     ├── StackOverflowError（栈溢出，如无限递归）
  │     ├── OutOfMemoryError（堆内存不足）
  │     └── NoClassDefFoundError（类定义找不到）
  └── Exception：程序层面可处理的异常
        ├── RuntimeException（运行时异常）：编译不检查，可处理可不处理
        │     ├── NullPointerException        空指针
        │     ├── ArrayIndexOutOfBoundsException 数组越界
        │     ├── ClassCastException          类型转换错误
        │     ├── ArithmeticException         算术异常（如除0）
        │     ├── NumberFormatException       数字格式错误
        │     ├── IllegalArgumentException    非法参数
        │     ├── ConcurrentModificationException 并发修改（遍历中修改集合）
        │     └── IndexOutOfBoundsException   越界（List/String等）
        └── 其他 Exception（编译时异常/受检异常）：必须在编译期处理
              ├── IOException                 输入输出异常
              ├── FileNotFoundException       文件未找到
              ├── ParseException              解析异常
              ├── SQLException                数据库异常
              ├── ClassNotFoundException      类未找到
              └── InterruptedException        线程中断

try-catch-finally 详解 ​

java
try {
    // 可能出异常的代码
    // 一旦某行抛出异常 → 跳过try内后续代码，跳到catch
} catch (异常类型1 e) {
    // 依次匹配catch，匹配成功则执行。多个catch时子类在前、父类在后
    // JDK7+ 可以用 | 合并：catch (IOException | SQLException e)
} catch (异常类型2 e) {
    // 处理异常类型2
} finally {
    // 无论是否异常、是否return，都会执行（除了 System.exit(0)）
    // 典型用途：关闭资源（IO流、数据库连接、网络连接）
}
// try-catch后：没有异常或catch处理完毕后，继续执行此处代码

finally 与 return 的陷阱 ​

java
public static int test() {
    int x = 10;
    try {
        return x;       // ① 准备返回10
    } finally {
        x = 20;         // ② finally确实执行了
    }
    // 返回值仍然是 10！因为 return 时已经把值复制到返回槽了
}

public static int test2() {
    try {
        return 10;      // ① 准备返回10
    } finally {
        return 20;      // ② finally的return覆盖了try的return → 返回20
    }
}
// 结论：不要在finally中写return，会吞掉try中的异常和返回值

public static void deleteDir(File dir) {
    File[] files = dir.listFiles();
    if (files != null) {
        for (File f : files) {
            if (f.isDirectory()) deleteDir(f);  // 先删里面的

}

四、多线程 ​

核心概念 ​

概念说明
进程运行中的程序，操作系统分配资源的最小单位，进程间内存隔离
线程进程中的执行路径，CPU调度的最小单位，同进程线程共享堆和方法区、独享栈和PC寄存器
并发同一时间段内多个线程交替执行（单核CPU快速切换，宏观并行微观串行）
并行同一时刻多个线程在多个CPU核心上同时执行（多核CPU）
高并发大量请求同时或短时间内到达，系统需要高效处理（线程池 + 队列是关键手段）

生产者消费者（等待唤醒机制） ​

java
// ★ 经典方式：Object的 wait/notify（只能在同步代码块中）
public class ProducerConsumer {
    private static final Object LOCK = new Object();
    private static boolean produced = false;

    // 生产者
    static class Producer implements Runnable {
        public void run() {
            synchronized (LOCK) {
                if (produced) {               // 已经生产，等待消费
                    try { LOCK.wait(); } catch (InterruptedException e) {}
                }
                System.out.println("生产了一个产品");
                produced = true;
                LOCK.notify();                 // 唤醒消费者
            }
        }
    }

    // 消费者
    static class Consumer implements Runnable {
        public void run() {
            synchronized (LOCK) {
                if (!produced) {              // 没有产品，等待生产
                    try { LOCK.wait(); } catch (InterruptedException e) {}
                }
                System.out.println("消费了一个产品");
                produced = false;
                LOCK.notify();                 // 唤醒生产者
            }
        }
    }
}

五、线程池 ​

为什么用线程池 ​

线程创建/销毁的开销很大（分配栈内存、线程本地存储等），频繁创建严重影响性能。线程池通过复用已创建的线程来降低开销，同时能控制最大并发数和排队策略。

九、动态代理 ​

不修改原类代码的情况下，对方法进行增强（日志、事务、权限控制、性能统计等）。

JDK动态代理（基于接口） ​

java
public class LogProxy {
    // 创建代理对象（核心方法）
    public static Object createProxy(Object target) {
        return Proxy.newProxyInstance(
            target.getClass().getClassLoader(),   // ①类加载器
            target.getClass().getInterfaces(),    // ②实现的接口列表
            new InvocationHandler() {             // ③处理器（增强逻辑在此）
                @Override
                public Object invoke(Object proxy, Method method, Object[] args)
                        throws Throwable {
                    // === 前置增强 ===
                    System.out.println("[" + method.getName() + "] 开始执行");
                    long start = System.currentTimeMillis();

                    // 调用原对象的方法
                    Object result = method.invoke(target, args);

                    // === 后置增强 ===
                    long end = System.currentTimeMillis();
                    System.out.println("[" + method.getName() + "] 执行完毕，耗时："
                        + (end - start) + "ms");
                    return result;
                }
            }
        );
    }
}

// 使用——只能代理接口方法
UserService service = new UserServiceImpl();
UserService proxy = (UserService) LogProxy.createProxy(service);
proxy.save();    // 自动打印日志+计时
proxy.delete();  // 同上

加载流程：

  1. 收到类加载请求
  2. 检查该类是否已被加载
  3. 未加载则向上委派给父加载器尝试加载
  4. 父加载器无法加载时，子加载器才自己加载

好处：

  • 避免类的重复加载（每个类只加载一次）
  • 防止核心 API 被篡改（如自定义 java.lang.String 加载不到，因为 Bootstrap 已经加载了核心 String）

类加载过程 ​

加载 → 验证 → 准备 → 解析 → 初始化
 │       │      │      │      └─ 执行 clinit()：初始化静态变量赋值、静态代码块
 │       │      │      └─ 将符号引用转为直接引用（内存地址）
 │       │      └─ 为静态变量分配内存，设默认值(0, null, false)
 │       └─ 验证 class 文件安全性（文件格式、元数据、字节码、符号引用）
 └─ 将 .class 字节码读入内存，生成 Class 对象

元注解（注解的注解） ​

元注解可能取值说明
@TargetElementType.TYPE（类/接口）、FIELD（字段）、METHOD（方法）、PARAMETER（参数）、CONSTRUCTOR（构造方法）、LOCAL_VARIABLE、ANNOTATION_TYPE、PACKAGE、TYPE_PARAMETER（JDK8泛型）、TYPE_USE（JDK8任意类型使用处）限定注解能用在哪儿

自定义注解 ​

java
// 1. 定义注解
@Target({ElementType.METHOD, ElementType.TYPE})  // 可用于方法和类
@Retention(RetentionPolicy.RUNTIME)                // 运行时保留
public @interface MyTest {
    String value() default "";       // 属性定义：类型 属性名() default 默认值
    int timeout() default 0;
    String author() default "unknown";
}

// 2. 使用注解
@MyTest(value = "测试登录", timeout = 3000, author = "张三")
public void testLogin() { /* ... */ }

// 如果只有value属性且只赋值value，value= 可省略
// @MyTest("快速测试")  等价于  @MyTest(value = "快速测试")

// 3. 通过反射解析注解
Method method = clazz.getDeclaredMethod("testLogin");
if (method.isAnnotationPresent(MyTest.class)) {
    MyTest anno = method.getAnnotation(MyTest.class);
    System.out.println("测试名称：" + anno.value());      // "测试登录"
    System.out.println("超时时间：" + anno.timeout());     // 3000
    System.out.println("作者：" + anno.author());         // "张三"

    // 根据注解信息决定如何执行（简单版测试框架雏形）
    long start = System.currentTimeMillis();
    method.invoke(testInstance);
    long elapsed = System.currentTimeMillis() - start;
    if (anno.timeout() > 0 && elapsed > anno.timeout()) {
        System.out.println("测试超时！");
    }
}
