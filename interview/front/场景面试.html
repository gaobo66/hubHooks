面试题：一次性给你 10000 条数据，前端怎么渲染到页面上？ ​

长列表常见的 3 种处理方式：

  1. 懒加载
  2. 时间分片
  3. 虚拟列表

懒加载

懒加载的原理在于：只有视口内的内容会被加载，其他内容在用户滚动到视口时才会被加载。这可以显著减少初次加载的时间，提高页面响应速度。这样的好处在于：

  1. 节省带宽
  2. 提升用户体验

懒加载的缺点：懒加载只能应对数据不是太多的情况。如果列表项有几万甚至几十万项，最终会有对应数量的 DOM 存在于页面上，严重降低页面性能。

时间分片

时间分片的本质是通过 requestAnimationFrame，由浏览器来决定回调函数的执行时机 。大量的数据会被分多次渲染，每次渲染对应一个片段。在每个片段中处理定量的数据后，会将主线程还给浏览器，从而实现快速呈现页面内容给用户。

时间分片的缺点：

  1. 效率低
  2. 不直观
  3. 性能差

总结：无论是懒加载还是时间分片，最终都是将完整数量的列表项渲染出来，这在面对列表项非常非常多的时候，页面性能是比较低的。

虚拟列表

原理：设置一个可视区域，然后用户在滚动列表的时候，本质上是动态修改可视区域里面的内容。

实现思路：

  1. 实现定高的虚拟列表，指的定高是说列表项的每一项高度相同

    涉及到的信息：

    • 可视区域起始数据索引(startIndex)
    • 可视区域结束数据索引(endIndex)
    • 可视区域的数据
    • 整个列表中的偏移位置 startOffset

  2. 优化点

    • 动态高度
    • 白屏现象
    • 滚动事件触发频率过高

    1. 动态高度

      不固定的高度就会导致：

      • 列表总高度：listHeight = listData.length * itemSize
      • 偏移量的计算：startOffset = scrollTop - (scrollTop % itemSize)
      • 数据的起始索引 startIndex = Math.floor(scrollTop / itemSize)

      这些属性的计算不能再通过上面的方式来计算。因此我们会遇到这样的一些问题：

      • 如何获取真实高度？
        • 如果能获得列表项高度数组，真实高度问题就很好解决。但在实际渲染之前是很难拿到每一项的真实高度的，所以我们采用 预估一个高度渲染出真实 DOM，再根据 DOM 的实际情况去更新真实高度。
        • 创建一个缓存列表，其中列表项字段为 索引、高度与定位，并预估列表项高度用于初始化缓存列表。在渲染后根据 DOM 实际情况更新缓存列表。
      • 相关属性该如何计算？
        • 显然以前的计算方式都无法使用了，因为那都是针对固定值设计的。
        • 于是我们需要 根据缓存列表重写计算属性、滚动回调函数，例如列表总高度的计算可以使用缓存列表最后一项的定位字段的值。
      • 列表渲染的项目有何改变？
        • 因为用于渲染页面元素的数据是根据 开始/结束索引 在 数据列表 中筛选出来的，所以只要保证索引的正确计算，那么 渲染方式是无需变化的。
        • 对于开始索引，我们将原先的计算公式改为：在 缓存列表 中搜索第一个底部定位大于 列表垂直偏移量 的项并返回它的索引
        • 对于结束索引，它是根据开始索引生成的，无需修改。

    2. 白屏问题

      仅渲染可视区域的元素。此时如果用户滚动过快，会出现白屏闪烁的现象。

      之所以会有这个现象，是因为先加载出来的是白屏（没有渲染内容），然后迅速会被替换为表格内容，从而出现闪烁的现象。

      并且这种现象在越低性能的浏览器上面表现得越明显。

      解决思路：

      为了让页面的滚动更加平滑，我们可以在原先列表结构的基础上加上缓冲区，也就是整个渲染区域由 可视区 + 缓冲区 共同组成，这样就给滚动回调和页面渲染留出了更多的时间。

  3. 滚动事件触发频率过高

绑定的是 scroll 滚动事件，虽然效果实现了，但是 scroll 事件的触发频率非常高，每次用户一滚动就会触发，而每次触发都会执行 scroll 回调方法。

解决思路：

可以使用 IntersectionObserver 来替换监听 scroll 事件。

相比 scroll，IntersectionObserver 可以设置多个阈值来检测元素进入视口的不同程度，只在必要时才进行计算，没有性能上的浪费。并且监听回调也是异步触发的。

面试题：Vue 的 nextTick 是如何实现的？ ​

参考答案：

nextTick 的本质将回调函数包装为一个微任务放入到微任务队列，这样浏览器在完成渲染任务后会优先执行微任务。

nextTick 在 Vue2 和 Vue3 里的实现有一些不同：

  1. Vue2 为了兼容旧浏览器，会根据不同的环境选择不同包装策略：
  • 优先使用 Promise，因为它是现代浏览器中最有效的微任务实现。
  • 如果不支持 Promise，则使用 MutationObserver，这是另一种微任务机制。
  • 在 IE 环境下，使用 setImmediate，这是一种表现接近微任务的宏任务。
  • 最后是 setTimeout(fn, 0) 作为兜底方案，这是一个宏任务，但会在下一个事件循环中尽快执行。
  1. Vue3 则是只考虑现代浏览器环境，直接使用 Promise 来实现微任务的包装，这样做的好处在于代码更加简洁，性能更高，因为不需要处理多种环境的兼容性问题。

整体来讲，Vue3 的 nextTick 实现更加简洁和高效，是基于现代浏览器环境的优化版本，而 Vue2 则为了兼容性考虑，实现层面存在更多的兼容性代码。

function renderer(vnode, container) {
    // 1. 创建元素
    const el = document.createElement(vnode.tag);
    // 2. 遍历 props，为元素添加属性
    for (const key in vnode.props) {
        if (/^on/.test(key)) {
            // 如果 key 以 on 开头，说明它是事件
            el.addEventListener(
                key.substr(2).toLowerCase(), // 事件名称 onClick --->click
                vnode.props[key] // 事件处理函数
            );
        }
    }
    // 3. 处理children
    if (typeof vnode.children === 'string') {
        el.appendChild(document.createTextNode(vnode.children))
    } else if (Array.isArray(vnode.children)) {
        // 递归的调用 renderer
        vnode.children.forEach(child => renderer(child, el))
    }

    container.appendChild(el)
}

响应式系统

总结：当模板编译成的渲染函数执行时，渲染函数内部用到的响应式数据会和渲染函数本身构成依赖关系，之后只要响应式数据发生变化，渲染函数就会重新执行。

面试题：介绍一下 Vue3 内部的运行机制是怎样的？

参考答案：

Vue3 是一个声明式的框架。声明式的好处在于，它直接描述结果，用户不需要关注过程。Vue.js 采用模板的方式来描述 UI，但它同样支持使用虚拟 DOM 来描述 UI。虚拟 DOM 要比模板更加灵活，但模板要比虚拟 DOM 更加直观。

当用户使用模板来描述 UI 的时候，内部的 编译器 会将其编译为渲染函数，渲染函数执行后能够确定响应式数据和渲染函数之间的依赖关系，之后响应式数据一变化，渲染函数就会重新执行。

渲染函数执行的结果是得到虚拟 DOM，之后就需要 渲染器 来将虚拟 DOM 对象渲染为真实 DOM 元素。它的工作原理是，递归地遍历虚拟 DOM 对象，并调用原生 DOM API 来完成真实 DOM 的创建。渲染器的精髓在于后续的更新，它会通过 Diff 算法找出变更点，并且只会更新需要更新的内容。

编译器、渲染器、响应式系统都是 Vue 内部的核心模块，它们共同构成一个有机的整体，不同模块之间互相配合，进一步提升框架性能。

说一说渲染器的核心功能是什么？ ​

详细

参考答案： 渲染器最最核心的功能是处理从虚拟 DOM 到真实 DOM 的渲染过程，这个过程包含几个阶段：

挂载：初次渲染时，渲染器会将虚拟 DOM 转化为真实 DOM 并插入页面。它会根据虚拟节点树递归创建 DOM 元素并设置相关属性。 更新：当组件的状态或属性变化时，渲染器会计算新旧虚拟 DOM 的差异，并通过 Patch 过程最小化更新真实 DOM。 卸载：当组件被销毁时，渲染器需要将其从 DOM 中移除，并进行必要的清理工作。 每一个步骤都有大量需要考虑的细节，就拿挂载来讲，光是处理元素属性如何挂载就有很多需要考虑的问题，比如：

最终设置属性的时候是用 setAttribute 方法来设置，还是用给 DOM 对象属性赋值的方式来设置 遇到像 disabled 这样的特殊属性该如何处理 class、style 这样的多值类型，该如何做参数的归一化，归一为哪种形式 像 class 这样的属性，设置的方式有哪种，哪一种效率高 另外，渲染器和响应式系统是紧密结合在一次的，当组件首次渲染的时候，组件里面的响应式数据会和渲染函数建立依赖关系，当响应式数据发生变化后，渲染函数会重新执行，生成新的虚拟 DOM 树，渲染器随即进入更新阶段，根据新旧两颗虚拟 DOM 树对比来最小化更新真实 DOM，这涉及到了 Vue 中的 diff 算法。diff 算法这一块儿，Vue2 采用的是双端 diff，Vue3 则是做了进一步的优化，采用的是快速 diff 算法。diff 这一块儿需要我展开说一下么？

开发者在模板中书写事件绑定：

1

模板被编译器编译后会生成渲染函数，渲染函数的执行得到的是虚拟 DOM.

事件在虚拟 DOM 中其实就是以 Props 的形式存在的。在渲染器内部，会有一个专门针对 Props 进行处理的方法，当遇到以 on 开头的 Prop 时候，会认为这是一个事件，从而进行事件的绑定操作。

Vue 项目中前端路由传参的方式主要有这么几种：

  1. 路径参数： 这种方式直观，路径直接反映参数的结构。适合用于需要在路径中明确表示的参数，如资源 ID。

大文件上传方案 ​

大文件上传的核心是「分片 + MD5 校验 + 合并」，既解决超时问题，又实现秒传 / 断点续传；

实现步骤如下：

  1. 读取文件
  2. 文件切片

    切片方案

    1. 单个切片计算hash值，这样保证每一个切片都有hash值，并在所有的chunks的hash给后端，后端返回返回一个数组（还需要上传的hashId）
    2. 计算整个文件的hash值加单个切片索引，上次时由后端判断是否上传过

    无论那种都需要计算整个文件的hash值，且计算整个文件的hash都需要切片计算，避免内存溢出，页面卡顿，从性能上方案2更优，

  3. 计算hash值

    计算hash方案

    为了实现秒传/断点续传功能，hash值只能基于文件内容计算

    1. 全量基于切片文件内容计算
    2. 对于第一个和最后一个切片全量计算，其他切切片分别在前面、后面和中间取2个字节参与计算
    3. Web Worker 优化。将哈希计算移到后台线程，避免阻塞主线程，提升用户体验
    4. 并行计算优化；利用现代浏览器的并行处理能力，提高计算速度，但可能增加内存占用
  4. 文件上传;核心就是并发控制
  5. 合并切片

javascript
<script>
  import SparkMD5 from "spark-md5";
  import axios from "axios";

  // 核心配置（简洁化）
  const CHUNK_SIZE = 5 * 1024 * 1024; // 5MB/片
  const CONCURRENT_LIMIT = 3; // 并发数
  const BASE_URL = "http://localhost:3000";

  let file;
  let progress = 0;
  let status = "";
  let uploadedChunks = [];

  // 1.选择上传文件

  const handleFileSelect = async (e) => {
    file = e.target.files[0];
    if (!file) return;

    status = "计算文件md5...";
    const md5 = await calculateFileMD5(file);
    await checkFileMd5(md5, file);
  };
  // 2. 分片计算 MD5（避免大文件卡顿）
  const calculateFileMD5 = (file) => {
    return new Promise((resolve) => {
	  // 文件阅读器
      const reader = new FileReader();
	  // MD5计算实例
      const spark = new SparkMD5.ArrayBuffer();
	  // 计算总片数
      const chunks = Math.ceil(file.size / CHUNK_SIZE);
      let currentChunk = 0;

	   /**
       * 文件分片读取完成事件
       * @param {ProgressEvent<FileReader>} e - 包含读取结果的事件对象
       */
      reader.onload = (e) => {
        spark.append(e.target.result);
        currentChunk++;
        currentChunk < chunks ? loadNextChunk() : resolve(spark.end());
      };

	  	 // 如果还有未处理的分片，继续加载下一个分片
        // 如果所有分片都已处理完成，计算并返回最终的MD5值
        // spark.end()会基于所有已添加的分片数据生成完整的MD5哈希值
      const loadNextChunk = () => {
        const start = currentChunk * CHUNK_SIZE;
        const end = Math.min(start + CHUNK_SIZE, file.size);
        reader.readAsArrayBuffer(file.slice(start, end));
      };

      loadNextChunk();
    });
  };

  // 3. 校验 MD5（秒传/断点续传）
  const checkFileMd5 = async (md5, file) => {
    const res = await axios.post(`${BASE_URL}/file/check`, {
      md5,
      fileName: file.name,
      fileSize: file.size,
    });

    if (res.data.isExist) {
      status = "秒传成功！";
      progress = 1;
      return;
    }

	
    uploadedChunks = res.data.uploadedChunks || [];
    status = "开始上传切片...";
    await uploadChunks(md5, file);
  };

  // 4. 并发上传切片（核心简化）
  const uploadChunks = async (md5, file) => {
    const chunks = Math.ceil(file.size / CHUNK_SIZE);
    // 生成待上传切片列表（过滤已传）
    const needUpload = Array.from({ length: chunks }, (_, i) => i).filter(
      (i) => !uploadedChunks.includes(i),
    );

    let completed = 0; // 已完成上传的新分片数量
    const pool = []; // 并发池

	// 遍历需要上传的分片索引
    for (const index of needUpload) {
      // 控制并发数
      if (pool.length >= CONCURRENT_LIMIT) await Promise.race(pool);

      // 上传单个切片（含重试）
      const upload = async () => {
        try {
          const start = index * CHUNK_SIZE;
          const end = Math.min(start + CHUNK_SIZE, file.size);
          const formData = new FormData();
          formData.append("md5", md5);
          formData.append("index", index);
          formData.append("chunk", file.slice(start, end));

          await axios.post(`${BASE_URL}/file/upload-chunk`, formData);
          completed++;
          progress = (uploadedChunks.length + completed) / chunks;
        } catch (err) {
          // 失败重试1次
          await axios.post(`${BASE_URL}/file/upload-chunk`, formData);
        }
      };

      const p = upload();
      pool.push(p);
      p.finally(() => pool.splice(pool.indexOf(p), 1));
    }

    // 等待所有切片上传完成
    await Promise.all(pool);
    status = "合并切片中...";
    await mergeChunks(md5, file.name, chunks);
  };

  // 5. 合并切片
  const mergeChunks = async (md5, fileName, totalChunks) => {
    const res = await axios.post(`${BASE_URL}/file/merge`, {
      md5,
      fileName,
      totalChunks,
    });

    if (res.data.code === 200) {
      status = "上传成功！";
      progress = 1;
    } else {
      status = `合并失败：${res.data.message}`;
    }
  };
</script>

    {/if}

<template>
  <div class="upload-container">
    <!-- 文件选择 -->
    <div class="upload-header">
      <input 
        type="file" 
        ref="fileInput" 
        @change="handleFileChange" 
        style="display: none"
      >
      <button class="btn choose" @click="$refs.fileInput.click()">
        选择文件
      </button>
      <button 
        class="btn control" 
        v-if="showControlButton" 
        @click="handleControlClick"
      >
        {{ controlButtonText }}
      </button>
    </div>

    <!-- 进度条 -->
    <div class="progress" v-if="uploadProgress > 0">
      <div class="inner" :style="{ width: uploadProgress + '%' }">
        <span>{{ uploadProgress }}%</span>
      </div>
    </div>

    <!-- 下载链接 -->
    <div id="link" v-if="downloadLink">
      <a :href="downloadLink" target="_blank">{{ downloadLink }}</a>
    </div>

    <!-- 加载模态框 -->
    <div class="modal" v-if="isLoading">
      文件处理中...
    </div>
  </div>

<script setup>
import { ref, computed, onMounted } from 'vue'
import SparkMD5 from 'spark-md5' // 需要安装 spark-md5

// 响应式状态
const fileInput = ref(null)
const selectedFile = ref(null)
const fileInfo = ref(null)
const needs = ref([])
const uploadStatus = ref('unchoose') // unchoose | choose | uploading | pause | finish
const downloadLink = ref('')
const isLoading = ref(false)

// 计算属性
const showControlButton = computed(() => {
  return uploadStatus.value !== 'unchoose' && uploadStatus.value !== 'finish'
})

const controlButtonText = computed(() => {
  switch (uploadStatus.value) {
    case 'choose': return '开始上传'
    case 'uploading': return '暂停'
    case 'pause': return '继续'
    default: return ''
  }
})

const uploadProgress = computed(() => {
  if (!fileInfo.value) return 0
  const total = fileInfo.value.chunks.length
  const uploaded = total - needs.value.length
  return Math.ceil((uploaded / total) * 100)
})

// 文件选择处理
const handleFileChange = async (event) => {
  const file = event.target.files[0]
  if (!file) return
  
  selectedFile.value = file
  isLoading.value = true
  
  try {
    // 文件分片处理
    fileInfo.value = await splitFile(file)
    
    // 握手验证
    const response = await fetch('http://localhost:8000/api/upload/handshake', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        fileId: fileInfo.value.fileId,
        ext: fileInfo.value.ext,
        chunkIds: fileInfo.value.chunks.map(it => it.id)
      })
    })
    
    const result = await response.json()
    
    if (Array.isArray(result.data)) {
      needs.value = result.data
      uploadStatus.value = 'choose'
    } else {
      needs.value = []
      uploadStatus.value = 'finish'
      downloadLink.value = result.data
    }
  } catch (error) {
    console.error('文件处理失败:', error)
  } finally {
    isLoading.value = false
  }
}

// 控制按钮点击
const handleControlClick = () => {
  switch (uploadStatus.value) {
    case 'choose':
    case 'pause':
      uploadStatus.value = 'uploading'
      uploadPiece()
      break
    case 'uploading':
      uploadStatus.value = 'pause'
      break
  }
}

// 文件分片函数
const splitFile = (file) => {
  return new Promise((resolve) => {
    const chunkSize = 1024 * 1024 // 1MB
    const chunkCount = Math.ceil(file.size / chunkSize)
    let chunkIndex = 0
    const spark = new SparkMD5.ArrayBuffer()
    const fileReader = new FileReader()
    const chunks = []
    
    fileReader.onload = (e) => {
      spark.append(e.target.result)
      const chunkMD5 = SparkMD5.ArrayBuffer.hash(e.target.result) + chunkIndex
      chunkIndex++
      
      chunks.push({
        id: chunkMD5,
        content: new Blob([e.target.result])
      })
      
      if (chunkIndex < chunkCount) {
        loadNext()
      } else {
        const fileId = spark.end()
        resolve({
          fileId,
          ext: extname(file.name),
          chunks
        })
      }
    }
    
    const loadNext = () => {
      const start = chunkIndex * chunkSize
      const end = Math.min(start + chunkSize, file.size)
      fileReader.readAsArrayBuffer(file.slice(start, end))
    }
    
    const extname = (filename) => {
      const i = filename.lastIndexOf('.')
      return i < 0 ? '' : filename.substr(i)
    }
    
    loadNext()
  })
}

// 分片上传函数
const uploadPiece = async () => {
  if (!needs.value || needs.value.length === 0) {
    // 上传完成
    uploadStatus.value = 'finish'
    downloadLink.value = `http://localhost:8000/upload/${fileInfo.value.fileId}${fileInfo.value.ext}`
    return
  }
  
  if (uploadStatus.value !== 'uploading') {
    return
  }
  
  const nextChunkId = needs.value[0]
  const chunk = fileInfo.value.chunks.find(it => it.id === nextChunkId)
  
  const formData = new FormData()
  formData.append('file', chunk.content)
  formData.append('chunkId', nextChunkId)
  formData.append('fileId', fileInfo.value.fileId)
  
  try {
    const response = await fetch('http://localhost:8000/api/upload', {
      method: 'POST',
      body: formData
    })
    
    const result = await response.json()
    needs.value = result.data
    
    // 继续上传下一个分片
    if (uploadStatus.value === 'uploading') {
      uploadPiece()
    }
  } catch (error) {
    console.error('分片上传失败:', error)
    uploadStatus.value = 'pause'
  }
}

// 初始化
onMounted(() => {
  uploadStatus.value = 'unchoose'
})
</script>

Vue大型项目首屏加载优化方案 ​

提问

请问在某个使用 Vue 开发的大型项目中，当组件数量超过 50 个时，您是如何通过组件懒加载、路由优化等方式减少首屏加载时间的？具体采用了哪些技术方案，加载速度提升了多少？

首屏加载的本质是加载的资源体积越小，请求数越少，加载速度越快，所有优化手段都是围绕「让首屏只加载 能渲染出页面的最小必要资源」展开，非首屏资源全部延迟加载 / 按需加载。

核心核心优化思路

在 Vue 大型项目中，首屏加载优化的核心是 「拆」+「懒」+「压」+「缓」：

  1. 拆：按路由 / 模块拆分代码 chunk，按功能拆分组件，避免全量打包。
  2. 懒：路由懒加载为核心，非路由组件异步加载，第三方组件库按需引入。
  3. 压：打包时开启压缩、树摇、分包，服务端开启 Gzip/Brotli 压缩。
  4. 缓：利用浏览器缓存（分包第三方依赖、配置缓存策略），预取高频资源。

利用Chrome Lighthouse分析核心性能指标

指标含义优秀标准优化目标
FCP（首次内容绘制）浏览器首次渲染出内容的时间<1.8s<1.5s
LCP（最大内容绘制）首屏最大元素渲染完成时间<2.5s<2s
FID（首次输入延迟）页面响应用户首次输入的时间<100ms<50ms
CLS（累积布局偏移）页面加载过程中的布局变化<0.1<0.05

首屏加载时间：一般指LCP，即用户能看到首屏完整内容的时间，优化目标 < 3s（3G 网络）/<2s（4G/5G 网络）。

打包体积分析

  1. Vite 项目：vite-bundle-visualizer
  2. Webpack 项目：webpack-bundle-analyzer

具体实现方案 ​

首屏优化按以下顺序做，性价比最高，避免盲目优化：

  1. 分析体积：用打包体积分析工具（BundleAnalyzer/visualizer）定位大依赖 / 大组件。
  2. 路由懒加载：按模块拆分路由，配置懒加载，核心模块分包，低优先级模块关闭预取。
  3. 第三方组件库按需引入：用自动按需引入插件，剔除未使用的组件和样式。
  4. 组件懒加载：对弹窗、Tab、滚动触发的组件做懒加载，超大组件（Echarts）单独懒加载。
  5. 打包优化：配置分包策略，将第三方依赖拆分成独立 chunk，开启压缩、树摇，关闭 sourceMap。
  6. 静态资源优化：图片懒加载、压缩、转 WebP，静态资源 CDN 引入。
  7. 服务端配置：开启 Gzip/Brotli、HTTP/2，配置浏览器缓存、history 模式路由。
  8. 性能验证：用 Chrome DevTools/Lighthouse 分析指标，根据建议微调。
  9. 避坑检查：检查内存泄漏、过度预取、CDN 版本兼容等问题。

路由懒加载 ​

核心原理：webpack/Vite 会将懒加载的路由组件，打包成独立的「chunk 文件」，首屏仅加载「根路由 / 首屏路由」的 chunk，其他路由在「用户点击跳转时」才会请求对应的 chunk。

        path: '/user',
        name: 'User',
        redirect: '/user/list', // 重定向到子路由

                path: 'list',
                name: 'UserList',

// src/router/index.js

import Vue from 'vue'
import VueRouter from 'vue-router'

Vue.use(VueRouter)

// 1. 首屏核心路由（单独分包，优先级最高）
const Home = () => import(/* webpackChunkName: "module-home" */ '@/views/home/Index')
// 404/500全局错误页（单独分包，所有模块都可能用到）
const NotFound = () => import(/* webpackChunkName: "module-common" */ '@/views/common/404')
const ServerError = () => import(/* webpackChunkName: "module-common" */ '@/views/common/500')

// 2. 懒加载引入业务模块路由（核心：模块路由文件本身也懒加载）
const UserModule = () => import(/* webpackChunkName: "module-user" */ '@/router/modules/user')
//....
// 低优先级模块（如设置）：关闭预取，避免占用首屏资源
const SettingModule = () => import(/* webpackChunkName: "module-setting", webpackPrefetch: false */ '@/router/modules/setting')

// 3. 全局路由配置
const routes = [
    // 首屏路由（最高优先级）
    {path: '/', name: 'Home', component: Home},
    // 业务模块路由（展开）
    ...UserModule,
    ...SettingModule,
    // 错误页路由（放最后）
    {path: '/404', component: NotFound},
    {path: '/500', component: ServerError},
    {path: '*', redirect: '/404'} // 匹配所有未定义路由，重定向到404
]

// 4. 创建路由实例，关闭生产环境的路由导航日志
const router = new VueRouter({
    mode: 'history', // 用history模式，去掉#，需服务端配置（后面讲）
    base: process.env.BASE_URL,
    routes,
    scrollBehavior: () => ({y: 0}) // 路由跳转后回到顶部
})

// 5. 路由守卫（可选，首屏优化：路由跳转时再加载埋点/统计插件）
router.beforeEach((to, from, next) => {
    // 非首屏路由，加载统计插件（避免首屏加载）
    if (to.path !== '/' && !window._hmt) {
        const hm = document.createElement('script')
        hm.src = 'https://hm.baidu.com/hm.js?你的统计ID'
        document.head.appendChild(hm)
        window._hmt = true
    }
    next()
})

export default router

注释作用适用场景不适用场景
webpackChunkName自定义 chunk 文件名，同名称的懒加载模块会打包到同一个 chunk同一业务模块的所有路由 / 组件不同模块的组件
webpackPrefetch: true/false首屏加载完成后，浏览器空闲时预取该 chunk（默认 true）高频访问的模块（如用户 / 商品）低优先级模块（如设置 / 帮助）

组件懒加载 ​

非路由组件的按需加载组件懒加载的核心：仅当组件被「渲染到页面」时，才会加载对应的 js 文件。

  1. 点击触发的组件（弹窗 / 抽屉 / 下拉菜单)
    1. vue2：AddOrderModal: () => import('@/components/order/AddOrderModal')
    2. vue3:defineAsyncComponent + Suspense，带加载 / 错误兜底
  2. 滚动触发的组件（列表底部的更多组件 / 图表，）:懒加载组件 + 滚动监听
  3. Tab 切换的组件:动态组件 + 懒加载 + v-show
  4. 体积超大的组件（如 Echarts / 富文本，单独懒加载）:懒加载，甚至单独分包 + CDN 引入。

懒加载组件的内存泄漏：异步组件（如 Echarts、弹窗）销毁时，未销毁实例，导致内存泄漏，页面卡顿 ——在 onUnmounted/destroyed 中销毁实例。

工程化打包优化 ​

打包优化是核心兜底，通过分包、压缩、树摇、排除外部依赖，进一步降低首屏资源体积，同时利用浏览器缓存减少重复请求。

  1. Vue2 + Webpack（vue-cli）
javascript
// vue.config.js
const {defineConfig} = require('@vue/cli-service')
const CompressionPlugin = require('compression-webpack-plugin') // Gzip压缩
const BundleAnalyzerPlugin = require('webpack-bundle-analyzer').BundleAnalyzerPlugin // 体积分析
const path = require('path')

module.exports = defineConfig({
    // 1. 基础配置：关闭生产环境sourceMap（避免源码暴露，减少体积）
    productionSourceMap: false,
    // 配置别名，方便引入
    configureWebpack: {
        resolve: {
            alias: {
                '@': path.resolve(__dirname, 'src')
            }
        },
        // 2. 分包策略：将第三方依赖拆分成独立chunk，利用浏览器缓存
        optimization: {
            splitChunks: {
                chunks: 'all', // 对所有chunk进行分包
                cacheGroups: {
                    // 第三方依赖包（vue、vue-router、axios等）
                    vendor: {
                        name: 'chunk-vendors',
                        test: /[\\/]node_modules[\\/]/, // 匹配node_modules中的文件
                        priority: -10, // 优先级：越高越先分包
                        reuseExistingChunk: true // 复用已有的chunk
                    },
                    // 公共组件（项目中多次使用的组件）
                    common: {
                        name: 'chunk-common',
                        minChunks: 2, // 至少被2个组件引用才分包
                        priority: -20,
                        reuseExistingChunk: true
                    },
                    // 超大依赖单独分包（如echarts、xlsx）
                    echarts: {
                        name: 'chunk-echarts',
                        test: /[\\/]node_modules[\\/]echarts[\\/]/,
                        priority: 10 // 优先级高于vendor，单独分包
                    },
                    xlsx: {
                        name: 'chunk-xlsx',
                        test: /[\\/]node_modules[\\/]xlsx[\\/]/,
                        priority: 10
                    }
                }
            }
        },
        // 3. 插件配置
        plugins: [
            // Gzip压缩：生成.gz文件，服务端配置后返回压缩文件
            new CompressionPlugin({
                algorithm: 'gzip', // 压缩算法
                test: /\.(js|css|html|svg)$/, // 压缩文件类型
                threshold: 10240, // 文件大小超过10KB才压缩
                minRatio: 0.8 // 压缩率小于0.8才压缩
            }),
            // 体积分析插件：运行npm run build时，生成可视化体积图谱（可选，优化时打开）
            // new BundleAnalyzerPlugin()
        ]
    },
    // 4. 链式配置：进一步优化loader和插件
    chainWebpack: config => {
        // 开启图片压缩
        config.module
            .rule('images')
            .test(/\.(png|jpe?g|gif|svg)(\?.*)?$/)
            .use('image-webpack-loader')
            .loader('image-webpack-loader')
            .options({
                mozjpeg: {progressive: true, quality: 65},
                optipng: {enabled: false},
                pngquant: {quality: [0.65, 0.9], speed: 4},
                gifsicle: {interlaced: false}
            })
        // 关闭预取：仅手动开启高频模块的prefetch（避免预取太多资源，影响首屏）
        config.plugins.delete('prefetch')
        // 开启预加载：首屏核心资源预加载
        config.plugin('preload').tap(options => {
            options[0].fileBlacklist = options[0].fileBlacklist || []
            options[0].fileBlacklist.push(/\.map$/, /hot-update\.js$/, /runtime\..*\.js$/)
            return options
        })
    },
    // 5. 开发环境配置（可选）
    devServer: {
        open: true, // 启动后自动打开浏览器
        port: 8080,
        proxy: {
            // 接口代理，避免跨域
            '/api': {
                target: 'http://localhost:3000',
                changeOrigin: true,
                pathRewrite: {'^/api': ''}
            }
        }
    }
})

// vite.config.js
import {defineConfig} from 'vite'
import vue from '@vitejs/plugin-vue'
import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'
import {ElementPlusResolver} from 'unplugin-vue-components/resolvers'
import CompressionPlugin from 'vite-plugin-compression' // Gzip/Brotli压缩
import {visualizer} from 'rollup-plugin-visualizer' // 体积分析
import path from 'path'
import {createSvgIconsPlugin} from 'vite-plugin-svg-icons' // SVG图标优化

// 获取环境变量
const isProduction = process.env.NODE_ENV === 'production'

export default defineConfig({
    // 1. 基础配置
    base: isProduction ? '/prod-path/' : '/', // 生产环境公共路径（根据实际部署路径修改）
    resolve: {
        alias: {
            '@': path.resolve(__dirname, 'src') // 别名配置
        }
    },
    // 2. 插件配置
    plugins: [
        vue(),
        // 自动引入Element Plus组件/API
        AutoImport({
            resolvers: [ElementPlusResolver()],
            dts: 'src/auto-imports.d.ts'
        }),
        Components({
            resolvers: [ElementPlusResolver()],
            dts: 'src/components.d.ts'
        }),
        // SVG图标自动导入（优化SVG加载）
        createSvgIconsPlugin({
            iconDirs: [path.resolve(__dirname, 'src/assets/icons')],
            symbolId: 'icon-[dir]-[name]'
        }),
        // 生产环境开启压缩（Gzip/Brotli，Brotli压缩率更高）
        isProduction &&
        CompressionPlugin({
            algorithm: 'brotliCompress', // 优先用Brotli
            test: /\.(js|css|html|svg)$/,
            threshold: 10240,
            minRatio: 0.8
        }),
        isProduction &&
        CompressionPlugin({
            algorithm: 'gzip', // 兼容不支持Brotli的服务端
            test: /\.(js|css|html|svg)$/,
            threshold: 10240,
            minRatio: 0.8
        }),
        // 体积分析插件：运行npm run build时生成可视化图谱（可选）
        isProduction && visualizer({open: true, filename: 'dist/visualizer.html'})
    ],
    // 3. 构建配置（核心：分包、压缩、排除外部依赖）
    build: {
        // 关闭生产环境sourceMap
        sourcemap: false,
        // 开启压缩
        minify: 'esbuild', // Vite默认用esbuild，比terser快20倍，压缩率接近

        rollupOptions: {
            output: {
                // 自定义分包：将第三方依赖拆分成独立chunk
                manualChunks: {
                    // 基础依赖：vue、vue-router、pinia
                    vue: ['vue', 'vue-router', 'pinia'],
                    // 网络请求：axios
                    axios: ['axios'],
                    // 超大依赖单独分包
                    echarts: ['echarts'],
                    xlsx: ['xlsx'],
                    // UI组件库：element-plus（如果自动按需引入，可省略）
                    elementPlus: ['element-plus']
                }
            },
            // 排除CDN引入的依赖（不打包进项目，直接用window上的全局变量）
            external: isProduction ? ['echarts'] : [] // 示例：Echarts用CDN引入
        },
        // 生产环境打包时，清空dist目录
        emptyOutDir: true,
        // 配置打包文件大小限制（可选）
        chunkSizeWarningLimit: 1000 // 超过1000KB才报警告

    // 4. 开发环境配置
    server: {
        open: true,
        port: 3000,
        proxy: {
            '/api': {
                target: 'http://localhost:8080',
                changeOrigin: true,
                rewrite: path => path.replace(/^\/api/, '')

    },
    // 5. CSS配置
    css: {
        preprocessorOptions: {
            scss: {
                // 全局引入SCSS变量/混合器，无需每个组件手动引入
                additionalData: '@import "@/styles/variables.scss";'
            }
        }
    }
})

静态资源优化：图片 / 字体 / 样式 ​

  1. 图片优化
    1. 图片懒加载：用vue-lazyload插件，首屏仅加载「可视区域」的图片，非可视区域用占位图替代，滚动时再加载
    2. 图片压缩：无损 / 有损压缩:
      1. 开发时：用TinyPNG（https://tinypng.com/）压缩图片，无损压缩，体积降 50%+。
      2. 打包时：Vue2 配置image-webpack-loader，Vue3/Vite 可安装vite-plugin-imagemin插件自动压缩。
    3. 图片 CDN

    图片懒加载的闪屏：占位图尺寸和实际图片不一致，导致加载后布局偏移（CLS 升高）——给图片设置固定宽高，或用骨架屏占位。

服务端 / 网络优化 ​

核心手段：Gzip/Brotli 压缩、浏览器缓存、HTTP/2、CDN，

  1. Nginx 配置 Gzip/Brotli 压缩
nginx
server {
  listen 80;
  server_name your-domain.com; # 你的域名
  root /usr/share/nginx/html; # 项目部署目录
  index index.html;

  # 1. 开启Gzip压缩
  gzip on;
  gzip_types text/plain text/css application/javascript application/json image/svg+xml;
  gzip_min_length 10k; # 超过10KB才压缩
  gzip_comp_level 6; # 压缩级别（1-9，6平衡速度和压缩率）
  gzip_vary on; # 告诉浏览器支持压缩

  # 2. 开启Brotli压缩（需要Nginx安装brotli模块）
  brotli on;
  brotli_types text/plain text/css application/javascript application/json image/svg+xml;
  brotli_min_length 10k;
  brotli_comp_level 6;

  # 3. 浏览器缓存配置（核心：利用缓存减少重复请求）
  location ~* \.(js|css|png|jpg|webp|svg|gif)$ {
    expires 30d; # 静态资源缓存30天（强缓存）
    add_header Cache-Control "public, max-age=2592000";
    add_header ETag $request_filename; # 协商缓存
  }

  # 4. history模式路由配置（Vue路由history模式必配，避免刷新404）
  location / {
    try_files $uri $uri/ /index.html;
  }

  # 5. 禁止访问sourceMap（生产环境已关闭，双重保障）
  location ~* \.map$ {
    deny all;
  }
}
